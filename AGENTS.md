# Project notes

## Application structure

- The landing page is in `src/routes/index.tsx`.
- Telegram planning rules live in `src/lib/planner/rules.ts`; server-only bot and Telegram code live in `src/lib/planner/*.server.ts`.
- The Telegram webhook is `src/routes/api/public/telegram/webhook.ts`. It validates the secret header, records update IDs to prevent duplicate replies, and delegates message handling to the bot module.
- Supabase stores the single bot owner, recent chat memory, and processed Telegram updates.

## Change guidelines

- Never commit secrets or real values from local environment files.
- Keep Telegram and Gemini credentials in server-side environment variables. Never expose them through `VITE_*` variables.
- Keep planner rules independent from server services so they can be reasoned about separately.
- Keep `src/routeTree.gen.ts` generated by TanStack Router.
- Update the Supabase migration and generated database types together when changing tables.
